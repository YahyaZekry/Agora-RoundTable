Audit where a coach's sourcing is thin. Resolve the shared data dir and identify the coach from $ARGUMENTS (or the active session, or survey mode if empty). First show any open entries in PERSONAS/<slug>/research/_gaps.md. Then spawn the persona as a subagent, step OUT of character, and have it audit its own research/ honestly: what's missing, what's too thin, and what specific source would close each gap. Classify each gap by which command closes it: unmined (already on disk — either in transcripts/ but not research/, or in research/ but never surfaced into persona.md, which is the only kind a historical figure has; free to extract, /agora coach-update closes it), unresearched (needs a web search — /agora coach-update will offer to do it), user-only (needs a specific book or paywalled piece, or a decision only the user can make — name it in _gaps.md and tell the user; they drop the file in inbox/ then run /agora coach-update). Check both transcripts/ AND the research/ files before calling anything unresearched: an unmined gap is free and should never be sent to the web, and an empty transcripts/ folder does not mean there are none. Append to _gaps.md. If the file already exists in a different shape — free-form prose under ### Unmined / ### Unresearched / ### User-only headings, which is what post-debate audits produce — keep that shape and append to the matching section rather than rewriting someone else's audit. For a new file use `## Gap:` blocks with `Status: open`. Report grouped by class. Never route a gap to coach-refresh — coach-update closes all three kinds without rebuilding anything.

NEVER write anything into inbox/. That folder is the user's drop zone and the only file this plugin may create there is _sync-status.md. Do not park a question there as a note — questions belong in _gaps.md and in what you tell the user. A file the user did not create, sitting in the one folder they own, gets found and deleted; that has already happened. Never delete or modify what the user put there either, including after extracting it — extraction is a read.
